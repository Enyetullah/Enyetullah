## 🤖 1. Multimodal Biometrics Prototype

<div align="center">

<img width="90%" src="https://capsule-render.vercel.app/api?type=rect&height=105&color=gradient&text=Multimodal%20Biometrics%20Prototype%20%7C%20Flask%20Research%20Demo&fontSize=27&animation=fadeIn" />

</div>

**Repository:** [multimodal_biometric](https://github.com/Enyetullah/multimodal_biometric)

This project is a **Flask-based research prototype** that implements decision-level fusion using a simulated physiological factor and behavioral biometrics.

The system uses a password-based proxy to represent a physiological factor and combines it with behavioral signals such as keystroke dynamics and mouse movement. It also includes a facial biometric component using OpenCV, where users can enroll webcam-based face samples and generate a normalized face template for scoring.

> **Note:** This is a research demo only and should not be used in production.

### Main Features

- Registration and login system
- Password used as a stand-in for a physiological factor
- Behavioral enrollment through keystroke and mouse movement samples
- Per-user One-Class SVM model for behavioral biometrics
- Decision-level fusion at login
- Fusion formula: `D = α·P + β·B`
- Threshold-based authentication decision
- Step-up OTP when behavior looks suspicious
- Simple evaluation page with rough FAR and FRR estimates
- Facial biometric enrollment using webcam images
- OpenCV-based normalized face template generation
- Cosine similarity-based face scoring mapped to `[0,1]`
- Logging of authentication decisions
- Logs stored in `data/app.sqlite`
- Viewable authentication logs page

### How the System Works

The prototype combines different authentication signals:

| Component | Role in the System |
|---|---|
| **Password Proxy** | Simulates a physiological pass or fail score `P ∈ {0,1}`. |
| **Behavioral Biometrics** | Uses keystroke and mouse movement features to produce behavior score `B ∈ [0,1]`. |
| **One-Class SVM** | Trained per user using collected behavioral enrollment samples. |
| **Facial Biometric Score** | Uses OpenCV to compare a new face capture against the enrolled face template. |
| **Decision-Level Fusion** | Combines scores using `D = α·P + β·B`. |
| **Step-Up OTP** | Triggered when the physiological factor passes but behavior appears suspicious. |
| **Evaluation Page** | Reports rough FAR and FRR estimates after enough samples are collected. |

### How to Use

1. Register an account.
2. Go to the enrollment page.
3. Collect at least 8 behavioral samples.
4. Type and move the mouse for 6 to 8 seconds per sample.
5. Logout and then login again.
6. Use the login page checkbox to simulate the physiological factor.
7. After login, the system runs a short behavioral check.
8. The system fuses the physiological and behavioral scores.
9. If behavior is suspicious while the physiological factor passed, the system asks for a step-up OTP.
10. Use the evaluation page to view rough FAR and FRR estimates.

### Configuration

Optional environment variables:

```text
SECRET_KEY
FUSION_ALPHA       default: 0.5
FUSION_BETA        default: 0.5
FUSION_THRESHOLD   default: 0.6
```

### Methodology Mapping

| Research Concept | Prototype Implementation |
|---|---|
| **Physiological biometric** | Simulated with a server-held score `P ∈ {0,1}` to mimic pass/fail behavior. |
| **Behavioral biometrics** | Browser JavaScript collects keystroke and mouse movement features. |
| **Behavior model** | Server trains a per-user One-Class SVM. |
| **Behavior score** | Model returns a behavior score `B ∈ [0,1]`. |
| **Fusion** | Decision-level fusion using `D = α·P + β·B`. |
| **Step-up authentication** | Triggered when `P = 1` but behavior score is suspicious. |
| **Evaluation** | Rough FAR and FRR estimates are shown on the evaluation page. |

### Facial Biometric and Logs

The project also includes a facial biometric feature.

Users can use the Face page to enroll 5 to 10 webcam images. A simple OpenCV pipeline builds a normalized face template for each user and scores new captures using cosine similarity mapped to `[0,1]`.

When a real face score is available, the fusion gate prefers the face score. If it is not available, the system falls back to the checkbox simulation.

Authentication decisions are written to:

```text
data/app.sqlite → auth_logs
```

They can be viewed on the Logs page.

## 🧠 2. Computer Vision ExerGame for Stroke Rehabilitation

<div align="center">

<img width="90%" src="https://capsule-render.vercel.app/api?type=rect&height=105&color=gradient&text=Computer%20Vision%20ExerGame%20for%20Stroke%20Rehabilitation&fontSize=27&animation=fadeIn" />

</div>

**Repository:** [Exer-Game-for-Stroke-Rehabilitation](https://github.com/Enyetullah/Exer-Game-for-Stroke-Rehabilitaion)

This project is a webcam-based rehabilitation exergame designed to support upper-limb movement training after stroke.

The system uses computer vision to track hand movement and turns rehabilitation-style exercises into an interactive game-based experience. It also collects performance data that can be used for analysis, progress tracking, and future improvement.

### Main Features

- Webcam-based hand tracking
- MediaPipe and OpenCV integration
- Game-based rehabilitation interaction
- Movement tracking
- Performance logging
- Multiple movement modes
- Difficulty-based exercises
- Healthy-user benchmark comparison
- Optional machine learning personalization
- Designed with rehabilitation, accessibility, and usability in mind

### AI and Computer Vision Concepts Used

- Real-time hand tracking
- Computer vision-based interaction
- Human-computer interaction
- Movement data collection
- Performance analysis
- Healthcare-focused AI system design
- Assistive and rehabilitation technology

### Why This Project Matters

Rehabilitation exercises can be repetitive and difficult to stay motivated for. This project explores how computer vision and interactive software can make rehabilitation more engaging while still collecting useful movement data.

The goal is not only to make a game, but to create a system that can support structured movement practice, track performance, and provide a foundation for future AI-based rehabilitation tools.
